💡 기술적 독창성 — "돈 없이"가 아니라 "돈으로 살 수 없는" 설계

1. API 없이 자동화
Tistory API 종료(2024) → Paste Pipeline + RSS Sync로 API 없는 양방향 브릿지 구현. 업계에서 유사 사례 없음.
2. CSS-only 인터랙션
Tistory HTML 모드는 JS·on* 핸들러 금지. :checked·<details>·:target만으로 탭·아코디언·버튼·다크모드 전부 구현.
3. .txt 클립보드 표준
HTML 코드를 .html이 아닌 .txt로 전송 → 안드로이드 텍스트 편집기에서 열림 → 전체복사 가능. 확장자 하나로 UX 장벽 해결.
4. 원격 워크플로우 배포
checkout 안 된 원격 레포에 gh api PUT으로 workflow 직접 생성. 5레포 × tistory-sync.yml 배포를 5분 만에 완료.
5. 공짜 슈퍼컴퓨터
GitHub Actions = Ubuntu 24.04 + 7GB RAM + 무제한 실행. APK 빌드·오디오 렌더링·CAD·컴퓨트를 전부 Actions에서 무료 처리.
6. 1:1:1 매핑
티스토리:GitHub:Pages = 1:1:1. 일반 RSS 리더(전부 한곳)와 달리 채널별 독립 레포로 버전 추적·권한·히스토리 분리.

📐 이 설계가 증명하는 것

1. "무료"는 부가 효과일 뿐, 본질은 아키텍처다.
GitHub Free가 우연히 공짜인 게 아니라, Git + CI/CD + Pages + API 라는 완결된 플랫폼을 무료로 제공하기 때문에 가능한 설계. 단순히 "돈 아꼈다"가 아니라 "돈으로 살 수 없는 통합"을 구현한 것.
2. 제약이 설계를 좋게 만든다.
Tistory API 없음 → Paste Pipeline 발명. HTML 모드 JS 금지 → CSS-only 인터랙션. 안드로이드 .html 브라우저 렌더링 → .txt 표준. 모든 혁신이 제약에서 탄생.
3. 2계층 분리가 핵심이다.
사람 공간(LLM·티스토리·텔레그램)과 기계 공간(GitHub·Pages·Actions)을 분리하고 양방향 브릿지로 연결. 어느 한쪽이 멈춰도 다른 쪽은 살아있다. 단일 장애점 없음.
4. 확장은 복사-붙여넣기다.
7번째 채널이 필요하면? 레포 생성 → tistory-sync.yml 복사 → blog 변수만 바꾸면 새 채널 추가 5분. 한계 비용 0의 확장성.
