💬 대화 기록

01 Boss "ParksyTTS 이거 폰에서 실제로 돌아가는 거 맞냐" 14:23

이거 TTS 어떻게 할 거냐. ParksyTTS 우리 폰으로 실제 추론 가능한 거 맞는지 확인해 봐.

02 Grok "GPT-SoVITS v2Pro, parksy_v2 체크포인트 314MB 있다" 14:25

확인했다. parksy_v2 체크포인트 314MB 로컬에 있고, GPT-SoVITS v2Pro 아키텍처. 한국어 BERT 불필요해서 0-vector 처리 이미 들어가 있다. 의존성 3종(numba, librosa, torchcodec)도 해결 완료.

03 Claude "CPU-only 환경에서는 GPT stage decoder가 구조적 병목" 14:28

우리 환경이 CPU-only(is_half=False, device="cpu")라서 GPT autoregressive stage decoder가 bottleneck이다. 1500 iterations, ~3초/it → 단일 음성 생성에만 471초. VITS 디코더 ONNX export는 됐지만 GPT stage는 아직 PyTorch.

04 Boss "471초면 실사용 못 하잖아. 다른 방법 없냐" 14:32

3.5초 음성 만드는 데 7분 51초면 못 써. 다른 TTS 옵션 찾아봐.

05 GAP 🕳️ GPT-SoVITS 아키텍처 자체가 CPU 실사용에 부적합 14:35

발견: Autoregressive 모델(GPT stage decoder)은 CPU에서 구조적 병목이다. ONNX로도 해결 불가. GPT-SoVITS 자체가 GPU 전제 아키텍처.

GPT-SoVITS는 GPU 있는 환경에서나 의미 있는 도구. S21 CPU-only로는 접근 자체가 잘못됐다.
06 Claude "경량 TTS + RVC ONNX 조합. 생성 대신 변환" 14:38

대체 전략 3단계: ① Sherpa-ONNX Kokoro 한국어 (jf_alpha) — 공짜, Apache 2.0, 이미 S21에 설치됨. ② RVC ONNX INT8 — 누나 목소리 변환 (~72ms). ③ Grok TTS는 403이니 사용 안 함. 생성(Generate) 대신 변환(Convert) — RVC가 훨씬 가볍다.

07 Boss "SoVITS 878MB 그냥 삭제해. Kokoro부터 테스트" 14:42

SoVITS 싹 지워. parksy_v2 4개 파일 전부. Kokoro로 테스트 먼저 해 보고 억양이 어떨지 들어보자.

08 Grok "Kokoro jf_alpha RTF ~2x, 정상 오디오. 근데 일본인 억양이..." 14:50

Kokoro FP32 정상 작동. RTF ~2x, RMS 0.08. jf_alpha(sid=37)는 일본인 여성 성우라 한국어에 일본 억양이 섞인다. 품질은 나쁘지 않은데 "어눌한 발음"이 거슬릴 수 있다.

09 Boss "어눌한 발음 오히려 캐릭터다. 근데 Edge TTS도 테스트" 14:55

일본인 억양이 오히려 "한국어를 열심히 배우는 착한 일본인 AI"라는 차별화된 캐릭터성을 만든다. 완벽한 발음보다 기억에 남는 목소리가 낫다. 그래도 Edge TTS도 한번 돌려봐. 비교는 해야지.
