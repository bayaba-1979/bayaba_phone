Paste Pipeline

터미널에서 티스토리까지 — Claude Code → GitHub → Telegram → 5클릭 → 발행

🎯 이게 뭔가

Claude Code로 만든 HTML 페이지를, Telegram 첨부파일 하나로 받아서, 티스토리 HTML 모드에 5번 클릭으로 붙여넣는 파이프라인.
티스토리는 발행 API가 없다. 브라우저 GUI 자동화는 유지보수 비용이 사람 5클릭보다 크다. 그래서 이게 유일한 실용 솔루션.

🗺️ 전체 워크플로우

🤔 왜 이렇게 해야 하나

❌ 티스토리 API — 발행 API가 없다

티스토리 Open API는 읽기 전용이다. 글 목록, 카테고리, 댓글 조회는 가능하지만 글 발행·수정 API는 존재하지 않는다. 기술적으로 막혀 있다.

❌ API 자동화

API 엔드포인트 자체가 없음. 불가능.

✅ Paste Pipeline

API 없이도 발행 가능. 유일한 방법.

❌ GUI 자동화 (Selenium/Puppeteer) — 가성비 0

브라우저 자동화로 티스토리 글쓰기 화면을 제어할 수는 있다. 하지만:

문제설명
로그인 세션티스토리 로그인은 카카오 계정 연동. 세션 만료·2FA·보안문자 대응 필요
UI 변경티스토리 에디터는 주기적으로 UI 변경. 그때마다 셀렉터 수정 필요
서버 비용headless 브라우저를 24시간 유지하거나, 발행할 때마다 띄워야 함
디버깅발행 실패 시 원인 파악 어려움. 스크린샷·로그 수집 파이프라인 추가 필요
월 유지보수 비용 > 사람 5클릭 30초 × 월 10회. 자동화는 ROI가 마이너스.
❌ 티스토리 마크다운 모드로 충분하지 않나?

마크다운 모드는 인터랙티브 요소를 표현할 수 없다:

❌ 마크다운 모드

아코디언 ❌ · SVG 다이어그램 ❌ · CSS 애니메이션 ❌ · 다크모드 ❌ · 탭 ❌ · 맞춤 레이아웃 ❌

✅ HTML 모드

아코디언 ✅ · SVG ✅ · 애니메이션 ✅ · 다크모드 ✅ · CSS-only 탭 ✅ · flex/grid 레이아웃 ✅

Tistory HTML 모드는 <script>와 on* 이벤트만 필터링한다. <style>, <svg>, <details>, CSS 애니메이션은 전부 통과. JS 없이도 풀인터랙티브 페이지를 만들 수 있다.

❌ GitHub Pages만으로 충분하지 않나?

GitHub Pages는 기술적으론 완벽하지만, 한국 검색 생태계와 분리되어 있다.

기준GitHub PagesTistory
네이버 검색 노출거의 안 됨✅ 잘 됨
다음 검색 노출거의 안 됨✅ 매우 잘 됨
댓글 시스템별도 구축 필요✅ 기본 제공
방문자 통계별도 구축 필요✅ 기본 제공
한국 블로그 생태계없음✅ 이웃·구독·공감
결론: GitHub Pages는 글로벌 아카이브, Tistory는 한국 유입 채널. 둘 다 필요하고 서로 보완한다.

💻 터미널에서 무슨 일이 일어나나

1 Boss가 Claude Code에 프롬프트 입력

S21 proot Ubuntu 터미널에서 claude 실행. DeepSeek 모델로 구동.

예: "ParksyCapture 백서를 티스토리 HTML 형식으로 만들어서 텔레그램으로 보내"

비용: DeepSeek API = 토큰당 저렴. GitHub Actions = public repo 무료. 총 비용 $0.
2 Claude Code가 HTML 파일 생성·커밋

Write 도구로 templates/*.html 작성. 확인 사항:

  • JS-free (script 태그 없음)
  • CSS-only 인터랙티브 (details/summary, :checked, :target)
  • 다크모드 대응 (prefers-color-scheme + data-theme)
  • Tistory XSS 필터 통과 확인

→ git commit → git push 자동 실행.

📊 멀티채널 전략 — 하나의 콘텐츠, 다섯 개 채널

Paste Pipeline의 진짜 힘은 한 번의 코딩으로 5개 채널에 콘텐츠가 퍼진다는 것:

✨ Paste Pipeline의 철학

99%는 자동화한다. Claude Code가 코딩하고, GitHub Actions가 변환·전송한다.

1%는 사람이 한다. 티스토리 HTML 모드에 붙여넣는 5클릭. 이 1%가 없으면 콘텐츠는 GitHub에만 머문다.

완전 자동화가 기술적으로 불가능한 플랫폼에서, 가능한 모든 것을 자동화하고 마지막 인간 터치만 남긴 설계. 과도한 자동화는 ROI가 마이너스다. 30초 × 5클릭이 가장 효율적인 솔루션이다.
