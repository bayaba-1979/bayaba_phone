## 1. 목표 · 원칙

- **품질 아주 좋게** — "돌봄 데몬" 채널의 기준작이 될 수준. 양보다 밀도.
- **한 편씩** — 한 편마다 완결. 게이트 통과해야 다음 편으로.
- **페어 발행** — 모든 편 = **티스토리 글 + GitHub Pages 페이지** 한 쌍. 단일 원고(md) → 두 곳.
- **돌봄 ≠ 소망 구분** — 여기엔 돌봄(길 1)만. 라디오·노래 AI 등 소망(길 2)은 S21.

## 2. 총 편수: **10편** (Season 1)

> 한 켠(카테고리)씩, 총 다섯 켠을 한 바퀴 도는 구성. 10편이면 "돌봄 데몬이 무엇인지"가
> 완결된 하나의 서사(매니페스토 → 제도 → 스토리 → 기술)로 닫힌다.

**아크 구조:**
```
[토대] 매니페스토 (1편)
   ↓
[제도] 트랙 DW·DC·BL (3편)  ← "무엇을 돌봐야 하는가"
   ↓
[스토리] 대화록 (1편)        ← "누구의 하루인가"
   ↓
[기술] 솔루션 (5편)          ← "어떻게 기술로 돌보는가" = 돌봄 데몬 본체

## 4. 품질 기준 (편마다 통과해야 할 게이트)

1. **한 편 = 하나의 질문 + 하나의 답** — 제목이 곧 그 편의 질문.
2. **실물 원천 인용** — 스크립트/설정 실제 값을 인용(임계값 15%/45°C/500m 등). 추상 금지.
3. **비단정 표현** — 법령·의료는 "확인 창구 / 확인일"로. (helana_log 규칙 계승)
4. **민감정보 차단** — 실 GPS·주소·진료 원문·토큰 절대 금지. (헌법: 돌봄 데이터 공개 금지)
5. **페어 동기화** — 티스토리 본문과 GitHub Pages 페이지가 같은 원고에서 나온다.

## 5. 페어 발행 파이프라인

```
원고(md, 단일 원천)
   ├─→ [티스토리] post.py → mynote11605 카테고리 발행   (URL 불변)
   └─→ [GitHub Pages] helana_log docs/*.html 빌드       (coverage 게이트)
```

- 티스토리 = 업무일지/발행처, GitHub Pages = 원자재 창고+웹 전시 ([[reverse-publishing-pattern]]).
- 원고 위치: 돌봄 데몬 콘텐츠는 `helana_log/docs/` 하위(트랙/대화록/솔루션)에 두고, 티스토리 발행은 helena_phone 파이프라인이 가져간다.
