📚 티스토리 = 하이테크 IT 교재 플랫폼

무질서한 개발 히스토리를 체계적 커리큘럼으로 —
"교재화" 방법론의 발견
💡 발견의 순간: 2026-08-10, 3개 레포의 ~200건 문서를 티스토리로 이전하는 작업 중 깨달았다. 이건 단순한 "글 옮기기"가 아니다. 무질서한 개발 노트를 Part·Chapter 커리큘럼으로 재편하는, 하나의 독립된 출판 방법론이다.

🎯 무엇이 다른가 — 일반 블로그 vs 교재화 블로그

구분일반 기술 블로그교재화 블로그
구조생각나는 대로, 순서 없이Part·Chapter 위계, 선수-후행 관계
목적기록·공유·과시처음부터 끝까지 따라오면 기술 완성
독자 경험파편화된 정보 헤매기커리큘럼 따라 체계적 학습
완결성없음. 시작만 있고 끝은 없음각 Part가 하나의 역량을 보장

🔄 교재화 5단계 프로세스

  1. 전수 조사 — 모든 레포의 md/html 문서를 빠짐없이 나열. 빠진 문서가 있으면 커리큘럼에 구멍이 생긴다.
  2. 주제 클러스터링 — 유사 주제끼리 묶어 Part(대분류) 도출. 보통 6~10개 Part가 나온다.
  3. Chapter 분할 — 각 Part를 학습 단위로 쪼개기. Part당 2~6개 Chapter. 한 Chapter가 한 번의 학습 세션.
  4. 콘텐츠 매핑 — 각 Chapter에 해당하는 원본 문서 연결 + 우선순위(⭐⭐⭐/⭐⭐/⭐) 태깅.
  5. 순차 출판 — 우선순위순으로 md→HTML 변환 → Paste Pipeline → 티스토리 발행.

🏗️ 왜 티스토리인가

✅ 무료 + 무제한 글 + 커스텀 HTML/CSS 가능. 카테고리 2레벨이 Part·Chapter 구조와 정확히 일치한다. GitHub Pages보다 진입장벽이 낮고(클릭만으로 글 작성), 모바일에서도 글 작성 가능. 검색엔진 자연 유입도 얻을 수 있다.

🔁 자기 참조적 구조 — 교재화 방법론 자체도 교재가 된다

이 방법론의 가장 흥미로운 특성: "어떻게 교재를 만드는가"가 교재의 한 Chapter가 된다.

즉, 독자는 이 블로그에서:

  • "폰으로 AI 워크스테이션 구축하는 법"을 배우면서
  • "그 지식이 어떻게 교재로 구조화되었는지"도 동시에 목격한다

메타 인지와 실용 지식이 하나의 커리큘럼 안에서 전달되는 구조. 이게 이 방법론의 진짜 차별점이다.
