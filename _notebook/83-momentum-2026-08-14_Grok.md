## 1. 왜 이 기점인가

S21의 가장 중요한 가치는 **돌봄**이다. 그 위에서 하는 일은 **에이전트가 출판·미디어를 만들 수 있는 인프라**다.

그 인프라에 Grok을 꽂을 때, 예전에 「디자이너」로 열어 두고 일을 계속 얹었다.  
오늘 Boss가 플러그를 **두 칸으로 자른다.** 특히 영상 칸은 페이지 소개 공장이 아니다.

**45,000원이 사는 것:** 누나 사진 하나와 프롬프트만 있으면, 그 얼굴이 이어지는 10초 클립 + 성우 더빙을 수준 높게 만들고, 그걸 이어 다큐로 만든다.

## 2. 칸 ① — 웹페이지 · 웹 코드 디자이너

| 맡는 것 | 안 맡는 것 |
|---------|------------|
| 랜딩·문서 페이지의 정보 구조 · 톤 · 레이아웃 | 네이버/티스토리 원고 전담 |
| **실제로 도는 CSS/JS 웹 코드** | md→html 파이프 소유 (출판부 `_Claude`) |
| 아이콘 · 색 · 타이포 · 모바일 거터 | 전 수첩 커버리지 상시 가디언 (제3직 아님) |
| 자기가 손댄 페이지의 html | 무한 패치 루프 (반장) |

시안만 던지고 끝내지 않는다. 페이지를 그리고 **그 페이지가 돌게** 짠다.

## 3. 칸 ② — 다큐멘터리 PD (오늘 확정한 제품)

이게 구독의 본체다. `66`/`72`의 「페이지 캡처가 70%」가 아니다.

### 3-1. 입력 → 출력

```
[안드로이드] 누나 얼굴 사진 1장
      │  (이미 있는 안드로이드↔proot 브릿지)
      ▼
[proot + Grok 플러그]
      1. 사진 합성 — 그 얼굴이 장면 안에 앉는다
      2. Boss 프롬프트 — 내가 준 문장대로만
      3. 10초 영상 — Imagine I2V, 딥페이크급 연속성
      4. 성우 더빙 — 그 10초에 목소리를 얹는다
      ▼
[proot FFmpeg]  10초 + 10초 + … 이어 붙여 다큐
```

| 단계 | 누가 | 도구 |
|------|------|------|
| 사진 전달 | 폰 (이미 됨) | 안드로이드 ↔ proot 브릿지 |
| 얼굴 합성 | Grok 플러그 | `image_edit` / 참조 생성 |
| 10초 클립 | Grok 플러그 | `image_to_video` duration=10 |
| 성우 더빙 | Grok 플러그 + 로컬 폴백 | 보이스 / Helena RVC |
| 이어 붙이기 | 이 터미널 | FFmpeg concat |

### 3-2. 한 클립의 계약

1. 재료는 **올린 그 사진**이다. 다른 얼굴로 바꾸지 않는다.
2. 연출은 **Boss가 준 프롬프트**다. 플러그가 주제를 바꾸지 않는다.
3. 길이는 **10초**가 기본 단위다.
4. 품질 기준은 「공짜 페이지 캡처 슬라이드」가 아니다. **그 얼굴이 이어지는 딥페이크급**이다.
5. 성우는 클립에 더빙한다. 페이지 나레이션 공장과 다르다.
6. 다큐는 그 10초들을 **이어 붙인 것**이다.

### 3-3. 이 칸이 아닌 것

- 웹페이지를 스크롤하며 찍은 소개 숏폼 (`66`/`72`가 Grok 역할이라고 한 것)
- 페이지 전편을 그림으로 다시 그리는 것
- 브릿지 스틸 몇 장만 넣고 끝내는 것
- 네이버 원고 · 강의 집필 · 수첩 전체 커버리지
- 돌봄 판단 (길 1은 Boss)

가까운 옛 문서: `61-landing-6clip-bgm-plan_Grok.md`  
그때는 재료가 랜딩 페이지였다. **오늘은 재료가 누나 사진 1장**이다.
