## 2. 칸 ① — 잡지 한 장 → 즉시 웹 코드 · 프롬프트면 이미지 교체

잡지를 찍으면 **그 구도를 읽고 바로 돌아가는 HTML/CSS를 짠다.**  
프롬프트가 오면 그 자리에 앉힐 **이미지도 바꾼다.**

```
[잡지 스프레드 사진]
      ▼
1. 구도 읽기 — 그리드·여백·타이포·악센트
2. 즉시 웹 코드 — 그 구성의 페이지
3. (프롬프트 있으면) image_edit/gen 으로 그 칸의 이미지 교체
      ▼
/sdcard 또는 레포 페이지로 내림
```

| 맡는 것 | 안 맡는 것 |
|---------|------------|
| 찍은 잡지 **구도 → 즉시 웹 코딩** | 잡지 본문·사진을 통째로 다시 올려 내 것처럼 발행 |
| 프롬프트대로 **이미지 교체** | 수첩 커버리지 · 네이버 원고 (출판부) |
| 우리 사진/누나 사진을 그 구도에 앉히기 | 무한 패치 루프 (반장) |

구독이 쓰는 것은 **구도를 훔쳐 보는 눈 + 생성**이다.  
남의 잡지를 스캔본으로 재배포하는 일이 아니다.

## 3. 칸 ② — 다큐멘터리 PD (오늘 확정한 제품)

이게 구독의 본체다. `66`/`72`의 「페이지 캡처가 70%」가 아니다.

### 3-1. 입력 → 출력

```
[안드로이드] 누나 얼굴 사진 1장
      │  (이미 있는 안드로이드↔proot 브릿지)
      ▼
[proot + Grok 플러그]
      1. 사진 합성 — 그 얼굴이 장면 안에 앉는다
      2. 프롬프트 = **대사** — 그 10초에 하는 말
      3. 합성 컷 → 10초 I2V (딥페이크급 얼굴 연속)
      4. 그 대사를 성우로 더빙
      5. 클립을 이어 붙여 **다큐 한 편**
      ▼
[proot FFmpeg]  10초 + 10초 + … 이어 붙여 다큐
```

| 단계 | 누가 | 도구 |
|------|------|------|
| 사진 전달 | 폰 (이미 됨) | 안드로이드 ↔ proot 브릿지 |
| 얼굴 합성 | Grok 플러그 | `image_edit` / 참조 생성 |
| 10초 클립 | Grok 플러그 | `image_to_video` duration=10 |
| 성우 더빙 | Grok 플러그 + 로컬 폴백 | 보이스 / Helena RVC |
| 이어 붙이기 | 이 터미널 | FFmpeg concat |

### 3-2. 한 클립의 계약

1. 재료는 **올린 누나 실제 사진**이다. 다른 얼굴로 바꾸지 않는다.
2. 프롬프트는 **대사**다. 그 10초에 하는 말. 플러그가 대사를 지어 바꾸지 않는다.
3. 길이는 **10초**가 기본 단위다.
4. 품질 기준은 페이지 캡처가 아니다. **그 얼굴이 이어지는 딥페이크급 다큐 클립**이다.
5. 그 대사를 성우로 더빙한다.
6. 다큐는 그 10초들을 **이어 붙인 한 편**이다.

한계(거짓말하지 않음): I2V는 입모양 완전 싱크를 보장하지 않는다. 대사는 더빙으로 얹는다. 클립 사이 얼굴은 같은 참조 사진으로 고정한다.

### 3-3. 이 칸이 아닌 것

- 웹페이지를 스크롤하며 찍은 소개 숏폼 (`66`/`72`가 Grok 역할이라고 한 것)
- 페이지 전편을 그림으로 다시 그리는 것
- 브릿지 스틸 몇 장만 넣고 끝내는 것
- 네이버 원고 · 강의 집필 · 수첩 전체 커버리지
- 돌봄 판단 (길 1은 Boss)

가까운 옛 문서: `61-landing-6clip-bgm-plan_Grok.md`  
그때는 재료가 랜딩 페이지였다. **오늘은 재료가 누나 사진 1장**이다.
