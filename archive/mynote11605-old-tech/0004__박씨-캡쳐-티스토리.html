📦 개요 — ParksyCapture란

ParksyCapture (com.parksy.capture)는 Flutter 기반 Android 앱이다. Claude·Grok·ChatGPT 같은 AI 앱과의 대화를 Share Intent로 캡처해 마크다운 파일로 저장한다. 단순한 "캡처 도구"가 아니라, AI 시대 지식 관리 파이프라인의 첫 관문이다.

핵심 명제: AI와의 대화는 휘발성이다. ParksyCapture는 그 휘발성 대화를 영구 지식 자산으로 전환하는 인터페이스다. "생각의 스크린샷" 도구.

⚙️ 작동 원리 — 3단계 흐름

1단계: 캡처 (Capture)

사용자가 Claude·Grok 앱에서 "공유" 버튼을 탭하면 Android Share Sheet가 열린다. ParksyCapture를 선택하면 ACTION_SEND intent가 전달된다.

EXTRA_TEXT에 대화 내용 전체가 텍스트로 담기고, Flutter Dart 코드가 이를 정제해 YAML frontmatter + 마크다운 형식으로 저장한다.

AI 앱 대화 중 Claude·Grok·ChatGPT Share Sheet ParksyCapture 선택 ACTION_SEND EXTRA_TEXT = 전체 대화 EXTRA_STREAM = 이미지 (미처리) .md 저장 ParksyLog_*.md /sdcard/Download/parksy-logs/ParksyLog_20260725_080708.md ⚠ EXTRA_STREAM(이미지 URI)은 현재 미처리 — 이미지 없는 텍스트-only 캡처⚠ 토큰 필터링 없음 — ghp_·sk- 등 민감 문자열이 그대로 저장될 수 있음
2단계: 저장 (Store) — 이중 저장 전략

캡처된 .md 파일은 두 곳에 저장된다:

  1. 로컬 (S21 폰): /sdcard/Download/parksy-logs/ — 오프라인·즉시 접근
  2. 원격 (GitHub): helena751107/helana_log/logs/ — 영구 보존·검색·발행

이중 저장이 중요한 이유: 폰을 잃어버려도 GitHub에 모든 대화가 남아있다. 플랫폼 독립적 지식 보존.

UID 분석: 파일 소유자 UID = 10264 (Android 앱 샌드박스 전용). proot Ubuntu(UID 0)에서는 읽기 전용 접근만 가능 — ParksyCapture만 이 디렉토리에 쓸 수 있다. 파이프라인 연동 시 읽기 전용으로 충분.
3단계: 발행 (Publish) — GitHub Actions → Telegram → Tistory

GitHub에 push된 .md 파일은 자동으로 처리된다:

git pushhelana_logGitHub Actionslog_to_telegram.shMD 기본 / --html 선택Telegram@helena_logbotPART 1~N 청크Tistory복사+붙여넣기RSS 순환 피드백

💡 왜 필요한가 — AI 시대 지식 관리의 역설

AI와 대화할수록 지식은 더 빨리 사라진다. 한 세션에서 수십 개의 결정·분석·아이디어가 오가지만, 채팅 인터페이스는 본질적으로 휘발성이다. 스레드가 길어지면 컨텍스트 윈도우 밖으로 밀려나고, 새 세션은 리셋이며, "그때 그 결정 왜 했더라?"를 검색할 수 없다.

ParksyCapture가 메꾸는 4가지 구멍

판단 소실
❌ "왜 그렇게 했는지" 사라짐
✅ 질문→반박→수정→결정 전 과정 보존
기억 왜곡
❌ 며칠 지나면 기억이 흐려짐
✅ 타임스탬프 + 원본 텍스트로 정확한 복기
전수 불가
❌ 나만 아는 암묵지
✅ 대화록 자체가 교재 — 사고 흐름이 보임
검색 불가
❌ "어디에 적었더라?" 찾을 수 없음
✅ GitHub grep = 모든 대화 full-text 검색

🏗️ 지식 3층 구조 — 날것에서 발행까지

ParksyCapture가 있음으로써 가능해진 지식의 층위. 3층이 모두 있어야 지식이 산다:

Layer 3 — 발행 (Published)

Tistory HTML · GitHub Pages · YouTube · Naver
"찾아서 배울 수 있는" 층

Layer 2 — 정제 (Refined)

Fact / Feel / Gap / Fix / Next 구조화된 대화록
"읽으면 이해되는" 층

Layer 1 — 날것 (Raw)

ParksyCapture 로그 · 스크린샷 · 음성 메모
"있기만 해도 가치 있는" 층

Layer 3만 있으면? 과정이 안 보인다. 결과물은 있지만 "왜"가 없다.
Layer 1만 있으면? 검색이 안 된다. 데이터는 있지만 지식이 아니다.
3층이 모두 있어야: 날것 → 정제 → 발행의 흐름으로 살아있는 지식이 된다.

📖 사용 설명서 — 30초 가이드

설치
  1. APK 다운로드 (추후 Play Store 또는 GitHub Releases)
  2. Android "출처를 알 수 없는 앱" 허용
  3. 설치 완료 → 특별한 설정 불필요
캡처 방법
  1. Claude·Grok·ChatGPT 앱에서 대화 중
  2. 우측 상단 ⋮ → 공유
  3. 공유 대상 목록에서 ParksyCapture 선택
  4. 자동으로 .md 파일 생성 완료!
발행 방법 (표준 파이프라인)
  1. 캡처된 .md 파일을 helana_log/logs/에 git push
  2. GitHub Actions 자동 트리거 → Telegram @helena_logbot으로 전송
  3. Telegram에서 PART 1~N 순서대로 전체 복사
  4. Tistory 글쓰기 → 마크다운 모드 → 붙여넣기 → 발행
  5. (선택) HTML 모드가 필요하면 --html 플래그 사용

ParksyCapture는 이 전체 파이프라인의 시작점이다. 이 앱 없이는 어떤 대화도 기록되지 않고, 기록되지 않은 대화는 지식이 될 수 없다. 마치 저장 버튼 없는 워드프로세서로 글을 쓰는 것과 같다. 결과물은 있지만, 어떻게 거기에 도달했는지는 영원히 사라진다.

🎯 Boss의 취지 — 왜 이 파이프라인을 구축하는가

AI와 일하면서 "저장"을 하지 않는 것은, 저장 버튼 없는 워드프로세서로 글을 쓰는 것과 같다. 결과물은 있지만, 어떻게 거기에 도달했는지는 영원히 사라진다. 그리고 AI 시대에 "어떻게 도달했는가"는 "무엇을 만들었는가"만큼 중요하다. 더 나은 질문을 하기 위한 재료이기 때문이다.

4가지 전략적 목표

# 목표 설명
1 판단의 계보 모든 결정의 "왜"를 질문→반박→수정→결정 흐름으로 보존. 6개월 후에도 "왜 이렇게 했지?"에 답할 수 있다.
2 지식의 외장화 내 머릿속 암묵지를 대화록이라는 형식지로 변환. 나 아닌 사람도 읽고 이해할 수 있게.
3 검색 가능한 기록 GitHub grep 한 줄로 6개월치 대화 전체에서 키워드 검색. "어디 적었더라?"가 사라진다.
4 발행 파이프라인 날것 로그 → 정제 대화록 → Tistory·YouTube·Naver·GitHub Pages. 한 번의 캡처가 5개 채널의 콘텐츠로 증식한다.

✨ 결론 — "생각의 스크린샷"

ParksyCapture는 "생각의 스크린샷" 도구다.

코드를 찍는 스크린샷이 아니라, AI와의 사고 흐름을 찍는 도구.

그 스크린샷(마크다운 로그)이 3층 구조(날것→정제→발행)를 거쳐
검색 가능하고, 재사용 가능하고, 발행 가능한 지식 자산이 된다.
